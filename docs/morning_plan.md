# План на ранок 2026-10-08 і коротка практика pytest

Мета ранку: перевірити повний цикл на Muse, зберегти придатний журнал і прочитати
звіт. Не починати нове навчання моделі чи імпорт великих датасетів до цієї перевірки.

## 1. Підготовка — 5 хвилин

```bat
conda activate neuro_env
cd C:\Projects\NeuroTrainer
git status --short
```

Не використовувати `git add .`: у папці залишаються окремі зміни ноутбуків і
submission-файли. Код уже у гілці `fix/audit-2026-10-02`; нові персональні журнали
та звіти виключені з Git. Muse увімкнути, закрити застосунки, що тримають його
Bluetooth-з'єднання. Комфортно розмістити електроди.

## 2. Мовчазна сесія — 2–5 хвилин

```bat
python run_sleep_observer.py --minutes 2
```

Перевірити шлях `Session journal:`, придатність усіх каналів і появу
`sleep.ready: True` після безперервних 30 секунд. При відхиленні спочатку
розібрати конкретний канал і причину, а не підвищувати пороги. Ctrl+C зупиняє
сесію. Показник стадії — прогноз, не підтверджений діагноз сну.

## 3. Звіт — 10 хвилин

```bat
python analyze_session.py --latest
```

Разом прочитати status, valid/rejected observations, причини відхилення та
`insufficient_data`. Мовчазний запис не використовувати як доказ ефекту звуку.
Звернути увагу: Alpha/Beta у поточному звіті — відносні частки; зміна вказана
у процентних пунктах, а не в мкВ чи абсолютній потужності.

## 4. Коротка проба звуку — лише після перевірки перших трьох кроків

Спочатку погодити комфорт і вихід навушників. Режим `--audio` використовує
поточні обмежені правила, а не навчений персональний вибір. Не міняти одночасно
гучність, тембр, частоти та алгоритм: інакше неможливо пояснити спостереження.
Після короткої проби створити окремий звіт; різниця з тишею ще не є причинним доказом.

## 5. Навчання pytest — 15 хвилин

```bat
python -m pytest tests/test_session_analysis.py -q
python -m pytest tests/test_session_analysis.py::test_known_response_summary -v
python -m pytest -k damaged_nested -v
python -m pytest -q --run-data-heavy
```

- `python -m pytest`: запускає pytest саме з активного середовища Python.
- Шлях після pytest: обирає файл тестів; `::назва`: один конкретний тест.
- `-q`: короткий результат; `-v`: назви тестів і деталі.
- `-k`: відбір назв тестів за виразом.
- `--run-data-heavy`: наш власний параметр із `tests/conftest.py`; включає
  чотири перевірки з локальними Sleep-EDF файлами й вагами. Це не вбудована
  команда pytest і не запускає тренування чи Muse.
- `assert`: перевірка очікуваного результату; `pytest.raises`: очікувана помилка.
- `tmp_path`: тимчасова папка тесту; `monkeypatch`: контрольована підміна,
  наприклад відсутності Muse, без реального обладнання.

Почати з `test_known_response_summary`: задано Alpha=20 до дії та Alpha=22
після; очікувана різниця +2 п.п. Потім розібрати параметризований тест
`test_damaged_nested_fields_raise_readable_error`: різні пошкодження журналу
мають викликати зрозумілий ValueError. Це практика «дані → дія → перевірка».

Залишити окремий час для основної підготовки до PMP; технічну сесію обмежити
приблизно годиною, щоб знову не витратити весь день на побічні експерименти.
